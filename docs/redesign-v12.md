# 纸间 1.2：界面与系统集成

## 最终行为

- 以桌面便签为主要书写入口。便签库改为侧栏与自适应卡片，提供搜索、颜色、收藏、桌面筛选与排序，点击卡片回到独立便签。
- 统一纸张色、字体、按钮、留白和图标。设置放在便签库左下角，小窗的“选项”中也可以打开。
- macOS Dock 右键与菜单栏、Windows 任务栏右键任务和系统托盘，均接入新建、便签库及设置。
- 启动参数通过单实例管道交给正在运行的应用。多个入口不会各自启动一份数据管理进程。
- 登录后自动启动：macOS 13+ 使用 SMAppService.mainAppService，Windows 使用当前用户 Run 项。界面读取系统状态，必要时提供前往系统设置授权的入口。不会替用户默认开启。
- 全局新建默认使用 macOS ⌥⌘N / Windows Ctrl+Alt+N。录制、保存、启停与恢复默认均在设置里完成。注册冲突时保留原组合键；录制时暂停原快捷键，取消、关闭或失去窗口激活后恢复。
- macOS 显式启用 Dock 与常规应用激活模式，从应用包加载应用级图标；Info.plist 声明常规前台应用。旧实现仅为窗口设置图标，不能据此保证 Dock 图标存在。未取得旧进程状态，因此不将历史现象归因于单一原因。

## 验证结果

- Release 构建：0 警告，0 错误。28 项存储与集成检查全部通过，包括真实子进程的互斥与管道转发。
- macOS ARM64 正式应用成功启动，WKWebView 正常显示已有 Markdown 待办。11 张真实便签的全部 JSON 字段与升级前备份完全一致。
- 原生 UI 中检查了新版卡片库、设置、快捷键注册状态及录制 / Esc 取消。独立 QA 数据还检查了新建、颜色、编辑、自动保存、快捷键录制 / 保存和自启开关反馈。
- 在独立 QA 实例运行时，从另一个进程传入 `--settings` 成功转发，并退出次进程。
- QA 的 Dock 诊断：激活策略为 0（常规应用），应用图标成功加载；应用包通过 ad-hoc 签名验证。
- Windows x64 已成功跨平台发布，产物包含运行时与任务栏 / 托盘 / 启动项 / 全局快捷键代码。

## 验证边界

- 原生自动化工具向目标应用投递按键，未能完成真实跨应用全局按键触发验证；系统注册成功，尚需用实体键盘检查。
- 自启开关的启停反馈在隔离模式下验证；正式版成功读取实际 macOS 登录项状态（关闭）。没有为测试更改真实登录项，也没有进行注销 / 重登录。
- 未能通过原生自动化取得 Dock 的可操作界面，Dock 菜单内容与图标仅完成配置和运行诊断检查，仍需在 Dock 中实际右键确认。
- Windows 尚未进行实机交互测试。发布成功不等于 Windows 原生集成已全部验证。
- 本轮没有重新执行独立 Playwright 浏览器套件，也未做完整读屏和对比度评估。macOS 仍采用本地 ad-hoc 签名；对外分发需要开发者签名及公证。

## 数据与测试隔离

- 正式数据保持在系统 PaperNote 数据目录，升级前备份位于 `artifacts/backups/20261027-192722-pre-v12`。
- UI 样例截图来自独立的 `artifacts/desktop-qa/data`，未向真实便签写入测试内容。
