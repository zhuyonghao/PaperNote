# Windows 标题栏显示修复

Avalonia 12 的 Fluent 窗口装饰会在扩展客户区上方绘制窗口标题，导致便签库、桌面便签及 Markdown 编辑器的自绘标题栏出现文字重叠。

- Windows 自绘标题栏使用派生窗口装饰主题，仅隐藏重复的标题文字，继续使用框架的窗口按钮、边框和命中检测。普通设置窗口保留完整标题栏。
- Windows 桌面便签只保留系统关闭按钮，右侧预留 50 DIP，给标题及新建、置顶、阅读和选项按钮留出空间。
- 显式隐藏 Fluent 装饰层的全屏按钮；便签小窗还隐藏最小化、最大化按钮。`CanMinimize` / `CanMaximize` 仅禁用操作，不会移除按钮及其布局空间；原本这些半透明按钮覆盖了“新建便签”和便签工具图标。
- 原生界面按平台指定字体：Windows 使用 Microsoft YaHei UI，macOS 使用 PingFang SC。
- 便签库卡片按实际滚动视口宽度计算列宽，并向下取整，避免边距、滚动条和小数舍入使末列换行、右侧留下整列空白。布局随视口宽度变化更新。

验证（Windows，2026-10-28）：

- `dotnet build src/PaperNote`：0 警告、0 错误。
- `dotnet run --project tests/PaperNote.Tests`：55 项检查通过。
- 独立测试数据目录实窗检查：便签库、桌面便签和 Markdown 编辑器无重复标题；便签小窗按钮分开显示；便签库浅色、深色及最大化布局正常。
- macOS 未做实机回归，窗口装饰主题的应用仅针对 Windows。

补充验证：在独立数据目录启动修复版本，默认 1120 DIP 窗口每行显示三张卡片；当前屏幕最大化后每行显示四张，右侧无多余整列空白。补充构建输出为 `artifacts/ui-review/`，0 警告、0 错误；55 项检查通过。

针对用户截图的二次修复：`artifacts/windows-ui-fixed/` 构建通过；便签库实窗及可访问性树确认装饰层仅保留 Minimize、Maximize、Close，“新建便签”文字不再被全屏图标覆盖。软件渲染对照未解决问题，最终保留原渲染设置。
桌面便签实窗确认新建、置顶、阅读、更多及关闭图标各自独立；Markdown 文档窗口的保存、阅读、更多与窗口按钮无覆盖。55 项检查再次通过。
