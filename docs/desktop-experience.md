# 桌面便签体验改版检查

> 此文记录 1.1 版本。1.2 新增设置、自启、全局快捷键和系统菜单，见 [新版检查记录](redesign-v12.md)。

本轮目标：日常停留在桌面便签上，快速记录与查看；整理、搜索和恢复内容时再进入便签库。

## 改版前的发现

1. **进入桌面便签：需要改进。** 启动先打开较大的便签管理窗口，独立便签入口是一个图标，日常使用路径偏长。旧管理界面中的短内容卡片宽度也不一致。
2. **在浮窗里书写：需要改进。** 格式工具一直占据顶部空间；换色、新建、收起和便签库入口不在浮窗内，置顶状态的表达较弱。

保留原有六种纸张配色和 Markdown 正文设计。减少小窗中的常驻工具，把管理功能放到需要时才打开的区域。

![原浮窗](../artifacts/desktop-review/02-sticky-before.png)

## 改版后的检查流程

1. **启动与恢复：通过。** 启动直接恢复桌面便签。退出并重新启动后，实际确认了测试正文、绿色纸张、置顶、17 px 字号、90% 不透明度和格式栏隐藏状态保留。收起状态与展开高度也保存在测试会话中。
2. **随手记录与调整：通过。** 从收起的便签顶部直接新建，立即粘贴 Markdown；检查待办、粗体、换色、置顶、字号、不透明度、源码切换和格式栏展开。更多选项在窗口内展开，避免覆盖正文的原生编辑区域。
3. **收起与展开：通过。** 便签能收起为标题条，快捷键可以恢复原高度与正文；不需要关闭或重新创建便签。
4. **往返便签库：通过。** 库中显示桌面数量和状态，桌面筛选正确显示两张测试便签。关闭便签库后，桌面便签继续保留。
5. **菜单入口：部分检查。** 在 macOS 菜单栏实际看到了新建、打开便签库、显示所有便签和暂时隐藏入口。Windows 系统托盘与多屏实际设备交互尚未实机验证。

## 验证与边界

- 新增及既有存储逻辑共 20 项检查通过，包括旧数据迁移、桌面布局保存、关闭状态、删除保护，以及高 DPI 和断开外接屏幕后的位置恢复计算。
- macOS 原生应用完成上述流程检查；本次浏览器交互通过原生 WKWebView 手动验证，没有重新运行 Playwright 浏览器套件。
- 图标按钮具备辅助功能名称；当前字号和不透明度选项有辅助说明。但未做完整读屏、对比度测量或 WCAG 合规评估，小窗操作目标仍适合鼠标与键盘使用。
- 独立测试目录：`artifacts/desktop-qa/data`。升级前保留了真实便签文件的完整备份，测试没有改写已有正文。
- 本轮不包含开机自启、全局快捷键、云同步或固定到系统桌面层。置顶指始终显示在其他普通窗口前面。
